## 发布命令

不带子命令运行 `verso` 会开始发布：

```sh
verso [OPTIONS]
```

| 参数                   | 默认值       | 说明                                                   |
| ---------------------- | ------------ | ------------------------------------------------------ |
| `--dry-run`            | `false`      | 预览发布，不写文件，也不执行会修改状态的 Git 命令      |
| `--json`               | `false`      | 以 JSON 输出 dry-run 结果；必须和 `--dry-run` 一起使用 |
| `--version <SEMVER>`   | 无           | 使用准确的目标版本，跳过交互式选择                     |
| `--config <PATH>`      | `verso.toml` | 读取其他配置文件                                       |
| `--yes`                | `false`      | 跳过确认；不会替你选择版本                             |
| `-V`、`--tool-version` | 无           | 打印 Verso CLI 版本并退出                              |
| `--help`               | 无           | 打印命令帮助                                           |

常用示例：

```sh
verso --dry-run
verso --dry-run --json
verso --version 0.26.0
verso --version 0.26.0-beta.1 --yes
verso --config config/release.toml
verso --tool-version
```

没有 `--version` 时，交互式菜单会提供 patch、minor、major、alpha、beta、rc 和自定义语义化版本。
当前版本是 prerelease 时，还会提供对应的 stable 版本。选择 prerelease channel 后会继续选择 base version。

stdin 或 stdout 不是终端时，Verso 会保留纯文本提示。脚本输入可以按名称选择，例如先输入 `beta`，
再输入 `minor`。

## `verso init`

创建初始 `verso.toml`：

```sh
verso init [--single | --workspace] [--force]
```

| 参数          | 说明                |
| ------------- | ------------------- |
| `--single`    | 生成单包配置        |
| `--workspace` | 生成 workspace 配置 |
| `--force`     | 覆盖已有配置        |

未明确指定模式时，命令会检测 `packages/*` workspace；没有这种目录结构时生成单包配置。

## `verso doctor`

在不开始发布的情况下检查仓库是否就绪：

```sh
verso doctor [--json]
```

检查范围包括配置解析、软件包发现、版本一致性、changelog 和 Cargo 路径，以及当前分支的 Git 上游状态。
`--json` 会生成适合 CI 使用的结构化输出。

## Package manager 脚本

Verso 作为 dev dependency 安装时，需要保留 package manager 的参数分隔符：

```sh
pnpm release -- --dry-run
pnpm release -- doctor --json
```
