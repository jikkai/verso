## 运行条件

Verso 通过 npm 软件包分发，并为支持的平台提供原生二进制文件。待发布仓库需要 Git、package
manifest 和已配置的上游分支。npm 软件包要求 Node.js 22.18 或更高版本。

## 安装

在 workspace 根目录添加 Verso：

```sh
pnpm add -D @amamo/verso
```

然后在根 `package.json` 中增加脚本：

```json
{
  "scripts": {
    "release": "verso"
  }
}
```

## 初始化配置

在仓库根目录运行：

```sh
pnpm release -- init
```

初始化器会写入 `verso.toml`；仓库存在 `packages/*` 时会自动识别这种 workspace 结构。可以用
`--single` 或 `--workspace` 明确指定模式，只在确实需要覆盖已有配置时使用 `--force`。

## 发布前检查

`doctor` 会校验配置解析、软件包发现、版本一致性、changelog 和 Cargo 路径，以及 Git 上游状态：

```sh
pnpm release -- doctor
```

CI 或其他自动化场景可以使用结构化输出：

```sh
pnpm release -- doctor --json
```

## 预览第一次发布

第一次真正发布前，先检查完整计划：

```sh
pnpm release -- --dry-run
```

预览会列出发现的软件包、当前版本与目标版本、计划修改的文件、changelog 内容、钩子和 Git 操作。
它不会写文件，也不会执行会修改仓库状态的 Git 命令。

计划无误后，可以交互式选择版本：

```sh
pnpm release
```

自动化场景也可以直接传入准确的语义化版本：

```sh
pnpm release -- --version 1.4.0 --yes
```

`--yes` 只跳过确认，不会替你选择版本。没有 `--version` 时仍会进入交互式版本选择。
